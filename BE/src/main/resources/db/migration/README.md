# 마이그레이션

## ⚠️ 이미 적용된 파일은 **주석 한 글자도 바꾸지 마라**

Flyway가 파일 체크섬을 `flyway_schema_history` 에 기록해 두고 기동할 때 대조한다.
바뀌면 앱이 **아예 뜨지 않는다**.

```
Migration checksum mismatch for migration version 3
-> Applied to database : 1613754412
-> Resolved locally    : -1135590748
```

2026-09-09에 문서 절 번호(`§3.5` → `§3.6`)를 코드 전체에 일괄 치환하다
`V3__member_withdrawal.sql` 의 **첫 줄 주석**을 건드려 로컬 BE가 죽었다.
운영에 나갔다면 배포가 통째로 실패했을 것이다.

그래서 마이그레이션 파일에는 **바뀔 수 있는 참조(문서 절 번호 등)를 적지 않는다.**

## 고쳐야 할 일이 생기면

* 스키마를 바꾸려면 **새 파일**을 추가한다(`V4__...sql`). 기존 파일을 고치지 않는다.
* 이미 바꿔 버렸다면 원래 내용으로 되돌리는 것이 먼저다.
  되돌릴 수 없으면 `flyway repair` 로 체크섬을 다시 기록해야 하는데,
  **파일과 DB의 실제 상태가 같다는 확신이 있을 때만** 쓴다.

## 엔티티를 바꿀 때

`ddl-auto: validate` 라 Hibernate가 스키마를 자동으로 고치지 않는다.
엔티티를 바꾸면 마이그레이션을 **함께** 추가해야 하며, 안 그러면 기동이 실패한다.
(그게 조용히 스키마가 바뀌는 것보다 낫다 — `docs/DEPLOY.md`)
