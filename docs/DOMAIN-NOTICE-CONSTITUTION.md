# DOMAIN-NOTICE-CONSTITUTION

공지·소식·운영 일정 도메인 원칙.

> 작성일: 2026-09-08. 이 문서는 원칙을 정의한다. 구현 규칙은 STATUTE에 둔다.

---

## 1. 책임

* 운영자가 회원과 방문자에게 알리는 **공지·소식·운영 일정**을 소유·관리한다.
* 이 글들의 생성·수정·삭제 및 조회(목록·단건)를 제공한다.
* 홈 화면의 캐러셀과 월간 달력에 **파생 정보로 제공**한다. 어떻게 보일지는 FE의 책임이다(ARCHITECTURE-CONSTITUTION §2).

---

## 2. 원칙

* **이 도메인의 글은 운영자만 쓴다.** 등록·수정·삭제는 `ROLE_ADMIN`만 할 수 있다.
  * 회원이 쓰는 글은 FEED, 회원이 여는 공연은 PERFORMANCE가 소유한다. 이 도메인은 **서비스가 자기 이름으로 말하는 것**만 담는다. 이 구분이 흐려지면 홈 캐러셀에 회원 글이 섞여 공지의 신뢰가 깨진다.
* **공지·소식·일정은 하나의 개체로 다룬다.** `type`(NOTICE/NEWS/EVENT)으로 구분하되 엔티티는 하나다.
  * 셋은 작성 주체·필드 구성·수명주기가 같고, 홈이 이들을 **한 번의 조회로 모아** 보여준다. 엔티티를 셋으로 쪼개면 캐러셀과 달력이 매번 세 방향 조회를 하게 되고, 공통 규칙(soft delete·권한·커버 이미지)이 세 벌로 복제된다.
* **달력 노출 여부는 `scheduledAt`의 유무로만 결정한다.** 별도의 "달력에 표시" 플래그를 두지 않는다.
  * 플래그를 따로 두면 "날짜는 있는데 달력엔 안 뜬다" / "달력에 뜨는데 날짜가 없다" 같은 모순 상태가 만들어진다. 상태가 하나면 모순이 생길 수 없다.
* **작성자는 원시 `authorId`(Long)로만 참조한다.** MEMBER 엔티티를 직접 참조하지 않는다(ARCHITECTURE-CONSTITUTION §4).
* **삭제는 soft delete다.** 논리 삭제(`deletedAt` 마킹)하며 모든 조회에서 제외한다.
* **조회는 공개다.** 이 도메인은 비인증 조회를 허용하는 **첫 도메인**이다.
  * 공개 응답은 인증 응답과 **별도의 DTO·컨트롤러**로 분리한다. 같은 DTO를 공유하면 나중에 필드가 하나 추가될 때 그것이 공개로 새는지 아무도 알아채지 못한다. 분리해 두면 공개 노출은 항상 **명시적인 선택**이 된다.
  * 공개로 여는 것은 **읽기뿐이다.** 쓰기 경로는 어떤 이유로도 공개하지 않는다.
* **커버 이미지는 FileService로만 저장한다**(DOMAIN-COMMON-STATUTE §7). 엔티티는 `storageKey`만 보관하고 URL은 저장하지 않는다.

---

## 3. 관계

* **MEMBER**: 작성자는 `ROLE_ADMIN` 회원이다. 어드민 화면에서 작성자를 보여줄 때만 MEMBER 서비스로 협력해 표시정보를 파생한다.
  * **공개 응답에는 작성자를 노출하지 않는다.** 공지는 개인 명의가 아니라 운영 주체의 발언이기 때문이다. 이는 개인정보 최소 노출과도 방향이 같다.
* **PERFORMANCE**: 홈 달력은 이 도메인의 일정과 PERFORMANCE의 공연을 **함께** 보여준다.
  * 두 소스를 하나의 화면용 응답으로 합치는 일은 **BFF(FE 쪽 계층)의 책임**이다. BE는 각 도메인이 **자기 데이터만** 공개 조회로 내려준다. ARCHITECTURE-CONSTITUTION §2("BE는 화면 로직을 갖지 않는다")를 지키기 위함이며, 동시에 §4의 도메인 경계도 지켜진다.
  * 공연 데이터의 소유·관리는 PERFORMANCE에 그대로 남는다. 이 도메인은 공연을 알지 못한다.
* **FEED**: 관계 없음. 회원 글과 운영 글은 섞지 않는다(§2).
* **VERIFIED-PERFORMER**: 관계 없음. 이 도메인의 작성 자격은 인증 연주자가 아니라 어드민이다.

---

## 4. 범위 밖 (현재)

* 댓글·좋아요·읽음 표시 — 공지는 일방향 전달이다. 반응이 필요하면 FEED에 글을 쓴다.
* 예약 발행(`publishAt`)·노출 기간(시작~종료) — 지금은 작성 즉시 공개, 삭제로 내린다.
* 카테고리·태그·키워드 검색 — 지금은 `type` 구분과 날짜 범위만.
* 푸시·이메일 알림 — 알림 인프라 도입 시.
* 개인화(특정 회원·역할에게만 보이는 공지).
* 첨부파일 — 커버 이미지 1장 외에는 두지 않는다.
* 공개 조회의 캐싱·레이트리밋 — 비인증 트래픽이 실제로 문제가 될 때 도입.
