* 2026-09-08 — 배포 대상을 **AWS EC2+RDS**로, 도메인은 **없이 IP부터** 가기로 결정. 준비해둔 설정이 HTTPS 전제라 **2단계 구성으로 재편**했다: `deploy/nginx.conf`(1단계 IP+HTTP, `server_name _`, 치환 불필요해 conf.d로 직접 마운트)와 `deploy/nginx.https.conf`(2단계 도메인+TLS, `${SERVER_NAME}` 치환이 필요해 templates로). compose의 nginx 블록은 1단계를 활성화하고 2단계 항목을 주석으로 남겼다. `.env.prod.example`도 IP·`ws://` 기준으로 고쳤다. `docs/DEPLOY.md`를 AWS 콘솔 실작업 기준으로 다시 썼고, 하루를 날릴 만한 함정 세 가지를 명시했다: (1) **RDS는 MySQL 8.0을 쓸 것** — 8.4는 Flyway가 "지원 테스트 안 됨" 경고를 낸다(로컬에서 실제로 확인), (2) **t3.micro(1GB)에서 Gradle 빌드는 그냥 죽는다** — 에러가 `Killed` 한 줄뿐이라 원인 찾기가 어렵다, 스왑 2GB 선행, (3) **Elastic IP 필수** — 인스턴스를 껐다 켜면 IP가 바뀌는데 `NEXT_PUBLIC_BE_WS_URL`은 빌드에 박혀 있어 채팅이 조용히 죽는다. 검증: `docker compose config`로 파생 환경변수(`WS_ALLOWED_ORIGINS`·`STORAGE_LOCAL_BASE_URL`·`KAKAO_REDIRECT_URI`) 치환이 맞는지 확인했고, 두 nginx 설정을 실제 nginx 이미지로 문법 검증했다(1단계 통과, 2단계는 인증서 파일 부재만 남음 — 치환은 정상).
