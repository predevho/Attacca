# 전역 레이아웃 기반 설계

## 목적

Attacca의 화면마다 흩어진 콘텐츠 폭과 여백 규칙을 공통 레이아웃으로 통일한다. 밝은 콘텐츠 커뮤니티라는 현재 방향과 색상 토큰은 유지하고, API·인증·도메인 동작은 바꾸지 않는다.

## 범위

1차에서는 공통 컨테이너를 만들고 홈, 피드, 구인, 채팅의 목록·대화 진입 화면에 적용한다. 기존 `Header`의 콘텐츠 폭도 같은 기준에 맞춘다.

상세, 작성, 관리자 화면의 내부 정보 구조와 시각 디자인 재구성은 후속 단위다. 이 작업에서 새 사이드바, 별도 디자인 시스템, 데이터 요청 변경은 만들지 않는다.

## 범위 확장 기록

2026-09-29 사용자 승인에 따라, 공개 상세·작성 화면에도 같은 프레임을 확장했다. 대상은 피드, 구인, 공연, 공지, 인증 연주자이며 정상·로딩·없음 상태를 포함한다. 관리자 화면은 운영 정보의 밀도와 작업 흐름을 별도로 설계해야 하므로 이 단위에서 제외한다.

## 구성

`FE/components/layout/PageContainer.tsx`는 페이지의 최상위 의미 요소를 만들고 세 가지 폭만 제공한다.

- `content`: 일반 목록과 홈의 읽기 폭, `max-w-5xl`
- `wide`: 대화처럼 가로 공간이 필요한 화면, `max-w-6xl`
- `narrow`: 작성·설정처럼 한 가지 작업에 집중하는 화면, `max-w-3xl`

모든 폭은 `w-full px-4`를 공유한다. 페이지는 개별 최대 폭을 직접 선언하지 않고 이 컴포넌트의 `width`와 추가 간격만 지정한다. `Header`도 `content` 폭에 맞춰 브랜드, 탐색, 계정 메뉴가 같은 수직선 위에 놓이게 한다.

## 사용자 경험

- 데스크톱에서는 탐색 메뉴와 페이지 콘텐츠의 좌우 기준선을 맞춘다.
- 모바일에서는 기존 햄버거 메뉴, Escape 닫기, 현재 페이지 표시를 보존한다.
- 채팅은 넓은 프레임을 사용하지만 입력창 하단 고정과 스크롤 동작에는 관여하지 않는다.
- 색상 토큰과 라이트/다크 테마의 대비 기준을 그대로 사용한다.

## 검증

`PageContainer`의 기본·넓은 폭을 렌더링 테스트로 검증한다. 기존 헤더 테스트와 각 대표 페이지 테스트를 실행하고, 데스크톱과 모바일 브라우저에서 메뉴·콘텐츠 폭·채팅 입력창이 겹치지 않는지 확인한다.
