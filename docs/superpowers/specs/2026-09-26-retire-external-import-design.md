# 외부 반입 기능 종료 설계

## 목적

KOPIS 공연과 대학 공지의 외부 반입 기능을 제품과 운영 경로에서 제거한다. 외부 사이트의 응답 형식, 차단 정책, API 키 운영 부담이 초기 서비스의 효용보다 크다는 판단에 따른다.

## 확정 결정

* KOPIS와 대학 공지 반입을 함께 종료한다. 한 원천만 남기지 않는다.
* 관리자 화면, 프런트 BFF, 백엔드 API, 수집기, 스케줄러, 설정과 테스트를 모두 제거한다.
* 운영 DB의 `import_run`, `imported_item` 테이블과 기존 Flyway 이력은 삭제하거나 되돌리지 않는다. 과거 데이터는 보존하고, 애플리케이션은 더 이상 이 테이블에 접근하지 않는다.
* 기존 외부 반입 설계·트러블슈팅 문서는 과거 기록으로 보존한다. 현재 TODO와 아키텍처 문서에는 기능 종료 결정을 반영한다.

## 제거 범위

### 프런트엔드

* `/admin/imports` 페이지와 해당 화면 컴포넌트·상태·변환 로직을 제거한다.
* `/api/bff/admin/imports/**` 프록시 경로와 계약 테스트를 제거한다.
* 관리자 허브의 외부 반입 진입점을 제거한다.

### 백엔드

* `com.back.domain.imports` 도메인과 컨트롤러, 수집·승인 서비스, 스케줄러, 저장소, DTO, 엔티티, 테스트를 제거한다.
* IMPORT 전용 예외 코드와 KOPIS XML·대학 HTML 수집 의존성을 제거한다. 다른 기능에서 사용하지 않는 의존성임을 확인한 뒤 build 설정에서 정리한다.
* `application.yaml`, Compose, `.env.prod.example`에서 KOPIS·대학 공지 반입 설정을 제거한다.

### 운영

* 코드 배포와 컨테이너 건강 상태를 확인한 뒤 EC2 `.env.prod`에서 `KOPIS_SERVICE_KEY`, `IMPORT_CONTACT` 및 IMPORT 전용 설정을 제거한다.
* 실행 중인 수집 작업이 없는 상태에서 배포한다. 종료된 기능의 과거 실행 이력은 DB에 남는다.

## 의도적으로 하지 않는 일

* 운영 DB 테이블 삭제, Flyway 이력 수정, 과거 반입 데이터 삭제
* 공지 도메인 또는 기존 공지 관리 기능 변경
* 외부 반입을 대체하는 새 공연·입시 기능 추가

## 완료 기준

* 관리자 허브와 FE 라우트에 외부 반입 진입점이 없다.
* BE에 IMPORT API·스케줄러·외부 수집 요청 코드가 없다.
* KOPIS/대학 반입 관련 환경변수와 불필요한 라이브러리가 제품 설정에서 제거된다.
* BE 전체 테스트, FE 테스트·타입 검사·lint·build가 통과한다.
* 배포 후 기존 로그인·공지 관리·채팅 등 반입과 무관한 주요 흐름이 정상이고, BE 컨테이너가 healthy 상태다.
