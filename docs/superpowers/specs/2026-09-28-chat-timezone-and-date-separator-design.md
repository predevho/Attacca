# 채팅 시간대 및 날짜 구분 설계

## 목적

채팅 메시지의 표시 시각을 한국 표준시(Asia/Seoul)로 일관되게 만들고, 긴 대화에서 날짜 경계를 쉽게 읽을 수 있게 한다.

## 확인된 현황

- 채팅 응답의 `createdAt`은 offset 없는 `LocalDateTime`이다.
- 운영 컨테이너 기본 시간대가 UTC이면 `LocalDateTime.now()`와 JPA 감사 시각이 UTC 벽시계 값으로 저장된다.
- FE `formatTime`은 문자열의 시간만 잘라 표시하므로 UTC 값을 KST로 바꾸지 못한다.
- 화면에는 날짜 구분선이 없어 날짜가 바뀐 대화의 맥락을 읽기 어렵다.

## 결정

### 운영 시간대

- BE Compose 환경에서 JVM 기본 시간대를 `Asia/Seoul`로 명시한다.
- 시간대 없는 `LocalDateTime`은 Attacca 운영 도메인에서 KST 벽시계 값으로 해석한다.
- FE는 채팅 시각에 별도 UTC 변환을 적용하지 않는다.

### 기존 데이터 보정 범위

Flyway 마이그레이션은 채팅 도메인의 자동 생성 시각에만 9시간을 더한다.

| 테이블 | 보정 컬럼 |
| --- | --- |
| `chat_message` | `created_at`, `updated_at` |
| `chat_room` | `created_at`, `updated_at`, `last_message_at` |
| `chat_participant` | `created_at`, `updated_at`, `left_at` |

사용자가 입력한 공연·공지 일정과 다른 도메인의 시간 값은 보정하지 않는다.

마이그레이션은 Flyway 이력으로 한 번만 실행되며, 이미 보정된 운영 DB에 재실행하지 않는다. 배포 전 DB 백업 또는 RDS 스냅샷을 확보한다.

### 화면 표시 규칙

- 날짜가 바뀌는 첫 메시지 앞에 접근 가능한 날짜 구분선을 표시한다.
- 날짜 구분선: `YYYY년 M월 D일 요일`.
- 각 메시지 시각: `오전/오후 h:mm`.
- 기존 메시지 id 정렬, 과거 이력 prepend 위치 보정, 하단 고정, IME 전송 방어는 바꾸지 않는다.

## 오류 처리와 되돌림

- DB 마이그레이션은 실패 시 앱 기동을 중단한다. 부분 적용을 숨기지 않는다.
- 데이터 보정은 운영 백업 또는 스냅샷에서만 되돌린다. SQL을 수동으로 다시 실행해 역보정하지 않는다.
- FE 날짜 파싱에 실패한 메시지는 기존 시간 문자열을 짧게 표시해 대화 렌더링 전체가 멈추지 않게 한다.

## 검증 기준

1. 채팅 시간/날짜 포맷과 날짜 그룹화 단위 테스트가 통과한다.
2. Flyway가 신규 DB와 기존 운영 DB에서 각각 의도한 순서로 적용된다.
3. 운영 배포 후 기존 메시지와 새 메시지가 KST 기준으로 표시된다.
4. 날짜가 달라지는 메시지 사이에 날짜 구분선이 하나만 나타난다.
