# 전역 내비게이션 + 악보지 테마 설계

작성일: 2026-08-18
배경: 2026-08-18 첫 실환경 스모크 검증에서 두 가지가 드러났다.
(1) 도메인 화면이 다 있는데 **화면 간 링크가 없어** URL을 직접 입력해야 도달한다.
(2) `globals.css`가 `prefers-color-scheme`으로 배경/전경만 뒤집는데 컴포넌트는 라이트 전용 색을 하드코딩해, **다크 환경에서 대비가 깨진다**.

## 결정 사항 요약

* 홈 = `/feed`. `/dashboard`는 제거한다(내비가 생기면 존재 이유가 없다).
* 헤더는 **플랫 구조**. 드롭다운·햄버거 없음. 좁은 화면은 `flex-wrap`으로 두 줄.
* `/profile`을 '내 것' 허브로 삼는다(인증 연주자·내 지원 현황을 여기 모은다).
* 서비스 컬러 = **헨레 악보 표지의 dove-blue 계열**. 배경은 악보 종이 베이지, 글자는 음표 검정.
  * 헨레는 공식 hex를 공개하지 않고 실물 표지도 용지 공급처(프랑스/바이에른)에 따라 편차가 있다. "정확한 재현"이 아니라 dove-blue 계열에서 고른 값이다.
* 브랜드는 **2톤**으로 나눈다. 면(버튼·뱃지)은 표지톤, 텍스트·링크는 한 단계 진한 톤 — 표지 인상을 지키면서 WCAG AA를 통과시키기 위함.
* 헤더는 **표지 바**. 라이트에서 짙은 표지, 다크에서 밝은 표지로 **반전**한다(헤더 = 표지, 본문 = 속지).
* 다크 팔레트를 이번 작업에 **함께** 적용한다. (범위가 커진다는 우려를 제기했으나 사용자가 재확인함. 리스크는 작업 순서 분할로 관리한다.)

## 확인된 현황 (조사 결과)

* Tailwind **v4** (`@tailwindcss/postcss ^4`) — `@theme`로 시맨틱 토큰을 정의하면 유틸리티가 자동 생성된다.
* 테스트가 클래스명을 **단 한 곳도 단언하지 않는다**(`toHaveClass` 0건). 색 교체는 기존 285개 테스트를 깨뜨리지 않는다.
* 색 사용 실측: 22개 조합 / 227곳.
  * `text-gray-500` 64 · `text-gray-400` 36 · `text-gray-700` 11 · `text-gray-600` 8
  * `text-red-600` 26 · `text-white` 26 · `bg-black` 22
  * `bg-gray-100` 7 · `bg-gray-200` 4 · indigo 계열 13 · amber 5 · green 3
  * **`bg-black` 22곳은 주요 버튼·활성 탭이다.** 토큰화하면 전부 dove-blue가 되어 앱 인상이 헤더뿐 아니라 전면적으로 바뀐다(의도된 변화).
* 미들웨어 matcher에 **`/recruitments`가 누락**돼 있다. 다른 도메인은 모두 있다. 2026-08-12 세 브랜치 병합 중 충돌 해소 과정에서 유실된 것으로 보인다. BE가 인증을 강제하므로 보안 구멍은 아니지만, 비로그인 접근 시 로그인으로 보내지 않고 빈 화면 + 401이 뜬다.
* 미들웨어 테스트가 **없다**.
* `/recruitments/applications/me`로 가는 링크가 **어디에도 없다**.
* `layout.tsx`의 metadata가 아직 `Create Next App` / `Generated by create next app`이다.

## 1. 색 토큰 체계

`FE/app/globals.css`에 Tailwind v4 `@theme`로 정의한다. 컴포넌트는 의미로만 쓰고 다크를 모른다. 다크는 `@media (prefers-color-scheme: dark)`에서 **토큰 값만** 교체한다.

| 토큰 | 종이(라이트) | 밤(다크) | 쓰임 | 대체 대상 |
|---|---|---|---|---|
| `paper` | `#F5F0E6` | `#1A1917` | body 배경 | 기존 `--background` |
| `surface` | `#FAF7F0` | `#232120` | 카드 면 | **신규 적용** (아래 주의) |
| `surface-muted` | `#EDE6D8` | `#2C2A28` | 미선택 칩·은은한 면 | `bg-gray-100/200` (11) |
| `ink` | `#171717` | `#EDE7DA` | 본문 | 기존 `--foreground`, `text-black`, `text-gray-800` |
| `ink-muted` | `#5C574E` | `#A8A296` | 보조 텍스트 | `text-gray-500/600/700` (83) |
| `ink-faint` | `#8A8378` | `#75706A` | 흐린 텍스트 | `text-gray-400` (36) |
| `line` | `#DED5C4` | `#34312E` | 테두리 | **신규 적용** (아래 주의) |
| `brand` | `#4E6E8E` | `#8FB0CE` | 버튼 배경·뱃지 | `bg-black`, `bg-indigo-600` (26) |
| `brand-strong` | `#3D5A80` | `#A9C6DE` | 링크·강조 텍스트 | `text-indigo-*` (7) |
| `on-brand` | `#F5F0E6` | `#16211C` | 브랜드 면 위 글자 | `text-white` (26) |
| `header` | `#3D5A80` | `#8FB0CE` | 헤더 바 배경 | (신규) |
| `on-header` | `#F5F0E6` | `#16211C` | 헤더 글자 | (신규) |
| `danger` | `#DC2626` | `#F87171` | 에러 | `text-red-600` (26) |
| `warn` | `#B45309` | `#FBBF24` | 경고 | amber 3종 (5) |
| `success` | `#15803D` | `#4ADE80` | 성공 | green 3종 (3) |

**`header`/`on-header`를 브랜드 토큰과 분리하는 이유**: 다크에서 헤더만 명암이 반전된다(라이트=짙은 표지+크림 글자 / 다크=밝은 표지+검정 글자). 브랜드 토큰에 얹으면 이 반전을 표현할 수 없다.

### 주의: `surface`와 `line`은 대체가 아니라 신규 적용

조사 결과 두 가지가 예상과 달랐다.

* **`bg-white`가 0곳이다.** 카드에는 배경 클래스가 아예 없고(`rounded-lg border p-4`) body 배경이 그대로 비친다. 종이 위에 얹힌 카드로 만들려면 `bg-surface`를 **새로 칠해야** 한다. 치환이 아니라 추가 작업이다.
* **테두리가 색 없는 bare `border`다.** Tailwind v4는 기본 테두리 색이 `currentColor`로 바뀌었으므로, 지금 테두리는 글자색을 따라가고 있다. 의도된 설계가 아니라 v4 기본값에 딸려온 결과다. `border-line`을 **명시적으로** 지정해야 한다.

즉 227곳 치환에 더해, 카드 배경·테두리 지정이 추가로 붙는다. 작업량 산정에 반영할 것.

### 검증한 대비비 (WCAG)

| 조합 | 대비 | 판정 |
|---|---|---|
| `ink` on `paper` (라이트) | 15.8:1 | AAA |
| `brand-strong` on `paper` (라이트) | 6.2:1 | AA |
| `on-header` on `header` (라이트) | 5.7:1 | AA |
| `ink` on `paper` (다크) | 14.3:1 | AAA |
| `brand-strong` on `paper` (다크) | 9.9:1 | AAA |
| `on-header` on `header` (다크) | 7.9:1 | AAA |

기각한 조합: 다크에서 헤더 바를 `#3D5A80`으로 두고 글자만 검정으로 하면 **2.5:1**로 기준(4.5) 미달이라 쓸 수 없다. 그래서 바 색 자체를 반전시킨다.

## 2. 헤더 컴포넌트

`FE/components/layout/Header.tsx` (신규 디렉터리). 클라이언트 컴포넌트 — 활성 경로 판정과 신원 조회가 필요하다.

**구조**

* 좌: 로고 `Attacca`(→ `/feed`) + 링크 4개 — 피드 `/feed` · 공연 `/performances` · 구인 `/recruitments` · 채팅 `/chat`
* 우: 닉네임 + 인증 뱃지(→ `/profile`) · 어드민(→ `/admin/verified-performers`, `role === 'ADMIN'`일 때만) · 로그아웃

**동작**

* 활성 경로는 `usePathname()`으로 판정한다. 정확히 일치가 아니라 **접두 일치**(`/feed/123`도 피드가 활성).
* 신원은 기존 `GET /api/bff/me/identity`를 재사용한다. `Me { id, nickname, role, verified }`.
* 신원 조회가 실패하면 **헤더를 렌더하지 않는다**(빈 헤더나 깨진 상태를 노출하지 않는다). fetch reject에 `.catch`를 건다 — 기존 BACKLOG의 unhandled rejection 항목과 같은 결함을 새로 만들지 않기 위함.
* 로그아웃은 기존 대시보드 로직을 옮긴다: `POST /api/bff/logout` → `/login`.
* 좁은 화면은 `flex-wrap`으로 두 줄. 햄버거·드롭다운은 만들지 않는다(상태·외부클릭·포커스 처리가 붙고, 정식 모바일 이식 때 한 번에 결정하는 편이 낫다).

**배치**

`app/layout.tsx`(루트)에 배치한다. 헤더가 필요 없는 화면은 **헤더 자신이 판단해서 렌더하지 않는다**.

```
usePathname()이 /login · /signup 으로 시작 → 즉시 null 반환 (신원 요청도 보내지 않는다)
```

대안으로 보호 페이지 7개(`feed`·`performances`·`recruitments`·`chat`·`profile`·`verified-performer`·`admin`)를 `app/(main)/` 라우트 그룹으로 옮기고 그 레이아웃에만 헤더를 두는 구조를 검토했으나, **이번 범위에서는 택하지 않는다.** 디렉터리 7개 이동은 이번 작업의 본질(내비·테마)과 무관하고, 이동 자체가 리뷰 잡음을 만든다. 나중에 그룹 구조가 필요해지면 그때 별도로 옮긴다.

경로 판정을 헤더 안에 두는 대신 별도 순수 함수(`shouldShowHeader(pathname)`)로 빼서 단위 테스트한다.

## 6. 테스트 전략

**색은 자동 테스트하지 않는다.** 클래스명 단언은 취약하고(기존 테스트도 `toHaveClass` 0건), 색이 실제로 맞는지는 사람 눈으로만 검증된다. 대신 다음과 같이 나눈다.

### 자동 테스트 (TDD)

* `shouldShowHeader(pathname)`: `/login`·`/signup`에서 false, 나머지 경로에서 true (순수 함수 단위 테스트)
* `Header`: 링크 4개 렌더 / 활성 경로 표시(접두 일치) / `role === 'ADMIN'`일 때만 어드민 링크 / 신원 조회 실패 시 미렌더 / 인증 경로에서 신원 요청을 보내지 않음 / 로그아웃 호출과 이동
* 라우팅: 루트·로그인·카카오 콜백·어드민 게이트의 이동 대상이 `/feed`인지
* 프로필: 닉네임·인증 뱃지 렌더, "내 지원 현황" 링크 존재
* **미들웨어**: matcher가 보호 대상 경로를 모두 덮는지 단언한다. 이번에 발견한 `/recruitments` 누락이 정확히 "병합 중 경로가 조용히 사라진" 사고라, 같은 사고를 막는 회귀 가드다. (신규 테스트 파일)

### 실화면 검증 (생략하지 않는다)

라이트/다크 각각 아래 8개 화면을 브라우저로 확인한다.

`/feed` · `/feed/[id]` · `/performances` · `/recruitments` · `/recruitments/[id]` · `/chat/[id]` · `/profile` · `/admin/verified-performers`

2026-08-18 채팅 결함이 "테스트는 전부 통과하는데 화면에서는 동작하지 않는" 유형이었다. 목으로 대체하거나 자동 검증이 불가능한 구간은 실기동 확인 전까지 미검증으로 취급한다.

### 회귀

기존 285개 테스트는 구조·동작 회귀 가드다. 색 교체만으로는 깨지지 않아야 정상이며, 깨진다면 그 자체가 신호다.

## 7. 작업 순서

1. 색 토큰 정의 (`globals.css`, 라이트/다크)
2. `Header` 컴포넌트 (TDD) + 레이아웃 배치
3. 라우팅 변경 + 미들웨어 matcher 수정 + 미들웨어 테스트 신규 + 기존 테스트 2건 갱신
4. 프로필 (닉네임·뱃지·내 지원 현황 링크)
5. 227곳 토큰 치환 + 카드 배경(`bg-surface`)·테두리(`border-line`) 신규 지정 — **도메인별로 분할**: 공통 → 피드 → 공연 → 구인 → 인증연주자 → 채팅
6. 라이트/다크 실화면 검증 (8화면 × 2)
7. 탭 제목·파비콘

5번을 도메인별로 쪼개는 이유는, 중간에 시각적으로 깨졌을 때 어느 도메인에서 깨졌는지 즉시 좁히기 위함이다.
