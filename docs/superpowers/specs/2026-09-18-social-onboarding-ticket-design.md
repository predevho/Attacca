# 소셜 신규 회원 온보딩 티켓 설계

## 1. 배경

카카오 OAuth 인증이 완료된 신규 회원을 일반 로그인과 같은 방식으로 처리하면서 가입 완료 전 상태에서 정식 인증 흐름과 약관 동의 흐름이 충돌했다. 신규 소셜 회원은 카카오 인증을 통과했지만 아직 Attacca의 닉네임과 필수 약관 동의를 확정하지 않은 상태다.

## 2. 목표

- 카카오 인증 성공과 Attacca 회원가입 완료를 분리한다.
- 신규 회원에게 정식 access/refresh 토큰 대신 짧은 수명의 온보딩 티켓만 발급한다.
- 온보딩 티켓으로 접근할 수 있는 API를 닉네임·필수 동의 완료로 제한한다.
- 온보딩 완료 시에만 정식 access/refresh 토큰을 발급한다.

## 3. 상태 흐름

```text
카카오 code 교환
  -> 회원/소셜 계정 생성 또는 기존 회원 확인
  -> 기존 완료 회원: 정식 access/refresh 발급
  -> 신규 또는 미완료 회원: onboarding ticket 발급
  -> FE 닉네임·약관 화면
  -> ticket 검증 + 닉네임 저장 + 동의 이력 저장
  -> 정식 access/refresh 발급
```

## 4. 티켓 규칙

- 형식: 서명된 JWT 또는 서버 검증 가능한 일회성 티켓. 일반 JWT 인증 필터에서 정식 access 토큰으로 취급하지 않는다.
- 만료: 발급 후 10분 이내.
- 대상: 회원 id와 `purpose=SOCIAL_ONBOARDING`만 포함한다.
- 권한: 일반 피드·채팅·공연·구인 API 접근 금지.
- 사용: 온보딩 완료 API에서만 검증한다. 완료 성공 시 티켓은 재사용할 수 없어야 한다.
- 비밀값: 티켓 값은 httpOnly·sameSite 쿠키로만 보관하며 브라우저 JavaScript에 노출하지 않는다.
- 완료 조건: 닉네임, 필수 약관 동의가 모두 유효해야 한다.

## 5. API 방향

- `POST /api/auth/oauth/kakao`
  - 완료 회원: 정식 토큰 쌍 반환
  - 미완료 회원: `onboardingTicket`과 `isNewMember=true` 반환
- `PATCH /api/members/me`
  - 기존 회원의 닉네임을 수정하고 기존 회원 신원 응답을 반환한다.
- `POST /api/members/me/onboarding`
  - 온보딩 티켓으로 닉네임과 필수 동의를 확정한다.
  - 성공 시 정식 access/refresh 토큰 쌍을 발급한다.
  - FE BFF가 응답의 토큰을 httpOnly 쿠키로 교체한 뒤 응답 본문에서는 숨긴다.

기존 PATCH 계약을 변경하지 않고 온보딩 완료를 별도 API로 분리해 기존 프로필 수정 화면과의 호환성을 유지한다. JWT의 `type=onboarding`은 온보딩 API 외 요청에서 차단하며, 완료된 회원에게 재사용할 수 없다.

## 6. 실패 처리

- 만료·위조·목적 불일치: 인증 오류로 거절한다.
- 필수 동의 누락: `CONSENT_REQUIRED`를 유지한다.
- 닉네임 충돌: 기존 `NICKNAME_ALREADY_EXISTS`를 유지한다.
- FE는 OAuth 제공자 오류와 온보딩 검증 오류를 같은 `oauth` 오류로 뭉개지 않고 사용자에게 다음 행동을 보여준다.

## 7. 보안 고려

- OAuth `state` 검증은 기존처럼 유지한다.
- 티켓에는 access/refresh 토큰을 넣지 않는다.
- 티켓 로그에 원문·회원 개인정보를 남기지 않는다.
- 온보딩 완료 전 기존 인증 필터의 일반 API 차단 정책을 유지한다.

## 8. 구현 순서

1. BE 응답 DTO와 티켓 발급/검증 컴포넌트 테스트 작성
2. 소셜 로그인 신규 회원 분기에서 티켓 발급
3. 온보딩 완료 시 티켓 검증 후 정식 토큰 발급
4. FE BFF가 티켓을 httpOnly 쿠키로 저장하고 닉네임 화면으로 이동
5. FE 실패 응답 매핑 및 만료 재시작 처리
6. 로컬 BE/FE 테스트와 staging 카카오 로그인 검증
